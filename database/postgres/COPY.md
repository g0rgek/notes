COPY загружает все строки за одну операцию, вместо использования серии команд INSERT. Команда COPY оптимизирована для загрузки большого количества строк; она менее гибкая, чем INSERT, но значительно снижает накладные расходы при больших объемах данных. Поскольку COPY — это одна команда, нет необходимости отключать автокоммит, если вы используете этот метод для заполнения таблицы.

Если вы не можете использовать COPY, может помочь использование PREPARE для создания подготовленного оператора INSERT, а затем использование EXECUTE столько раз, сколько необходимо. Это позволяет избежать некоторых накладных расходов, связанных с многократным анализом и планированием INSERT.

Обратите внимание, что загрузка большого количества строк с помощью COPY почти всегда быстрее, чем с помощью INSERT, даже если используется PREPARE и несколько вставок объединены в одну транзакцию.

COPY работает быстрее всего, если используется в той же транзакции, что и ранее выполненные команды CREATE TABLE или TRUNCATE. В таких случаях запись WAL не требуется, поскольку в случае ошибки файлы, содержащие вновь загруженные данные, будут удалены в любом случае. Однако это соображение применимо только тогда, когда wal_level имеет минимальное значение, поскольку в противном случае все команды должны записывать WAL.

## Отличие от Insert

## `INSERT`

```sql
INSERT INTO t VALUES (...), (...), (...);
```

Проходит **полный SQL-пайплайн** для _каждой строки_:
1. Parsing
2. Rewrite rules
3. Planning
4. Executing
5. Constraint checks
6. Index updates
7. WAL logging
8. Trigger execution
Executor обрабатывает **каждую строку отдельно**.

## `COPY`

```sql
COPY t FROM STDIN;
```

Работает **ниже SQL-уровня**:
- один parse / plan
- строки читаются **потоком**
- минимальные проверки
- данные подаются напрямую в storage engine

Это **специализированный bulk-loader**, а не SQL-операция в классическом смысле.
