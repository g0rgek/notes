## Горизонтальное
Горизонтальное делится на два типа: репликацию и шардинг. Репликация служит для масштабирования вычислений, шардинг — для масштабирования данных.  
  
В одной базе лежит миллиард строк. И база начинает тормозить. Можно создать еще один сервер с БД, создать такую же таблицу и перелить часть данных туда.

Такой сервер называется шард, их может быть несколько штук. В таком случае, для записи в шарды нужно выбрать ключ шардирования. Пусть это будет первичный ключ и шард будет высчитываться как primary key % shards.

Минусы:
- данные должны быть равномерно распределены по шардам (выбирать ключ шардирования)
- нужно избегать мультишард запросов
- сложный решардинг/ребалансировка (когда нужно добавить новый шард)
- невозможность использовать транзакции
- невозможно использовать JOIN
Примеры: [vshard](https://habr.com/ru/companies/vk/articles/436916/) (шардирования по хешам, виртуальные бакеты, которые ездят по серверам с БД)
## Вертикальное
Есть большая таблица с множеством полей.  Можно вынести некоторые связные поля в отдельные таблицы. И эти таблицы можно горизонтально масштабировать.
```
items
+------------------------------------------------------+
id | created_at | name | desc | specs | images | videos|
--------------------------------------------------------
1    01.02.2025   item1  apple  tag1     ...       ...
2    02.02.2025   item2  banana tag2     ...       ...


items                                          items_media
+-------------------------------------+    +--------------------+
id | created_at | name | desc | specs |    | id |images | videos|
--------------------------------------+    +--------------------+
1    01.02.2025   item1  apple  tag1         1    ...       ...
2    02.02.2025   item2  banana tag2         2    ...       ...


items                      items_metadata              items_media
+----------------------+  +-------------------+  +----+---------------+
id | created_at | name |  | id | desc | specs |  | id |images | videos|
-----------------------+  +-------------------+  +--------------------+
1    01.02.2025   item1     1     apple tag1       1    ...      ...
2    02.02.2025   item2     2    banana tag2       2    ...      ...
```
